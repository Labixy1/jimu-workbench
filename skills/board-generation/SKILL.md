# 生成画板

## 方法
1. 确定用户要表达的流程或关系，以用户说明或本次所选材料为依据；设计方案要与已经实现的事实区分。
2. 需要生成画板时读取 [references/graph-format.md](references/graph-format.md)，按当前任务的文件输出协议提供结构。简单顺序用diagram；模块分工、条件分支或反馈用graph。
3. page.content简要说明流程、来源与边界，保留准确原文引用。
4. 分组说明谁负责或哪类能力；节点说明具体动作；箭头说明流转、引用或返工。不把并列关系强行连成因果，不用节点数量冒充复杂度。
5. graph同一组的row自上而下排列，每行一个节点；标签精简，detail解释关键条件。输入、分支、结果与反馈需要能读懂，有依据才画异常或权限判断。

## 输出
普通对话使用运行时jimu-artifact协议，type为board；任务明确要求page结构时使用page。积木的本地布局工具将声明式步骤或关系生成Excalidraw图形，模型不写可执行绘图代码，也不把技能当成画板编辑器。
生成后可以预览、拖动图形和修改文字；用户点击加入资产才保存。

## 引用边界
引用已有画板只读取已保存文字，不识别截图、不推断箭头语义。不得编造来源、贡献或业务结果。
